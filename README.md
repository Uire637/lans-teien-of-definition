# 留白 · Personal Energy & Decision Companion

一个围绕**人的精力与生活感受**设计的轻量 Web App。帮助你回答「现在感觉如何」「接下来可以做什么」「今天是否已经足够」，而不是催促你清空待办。

使用 React 19、TypeScript、Vite 7、Tailwind CSS 4 和 Lucide 图标构建。没有后端、账号、AI API 或外部服务依赖，数据保存在当前浏览器的 localStorage 中。

## 本地启动

需要 Node.js **22.12+**（推荐 Node.js 24 LTS）和 npm。

```bash
npm ci
npm run dev
```

在浏览器打开终端显示的本地地址。开发服务器默认端口为 5173，监听所有网卡，方便容器内开发。请只在可信的本地开发环境使用开发服务器。

```bash
npm test           # Vitest 单元测试
npm run build      # TypeScript 类型检查 + Vite 生产构建
npm run preview    # 检查 dist 中的生产构建
```

如果容器内默认 npm 缓存目录不可写，可使用：

```bash
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
```

## 第一阶段已实现

- **每日精力预算**：1–10 点，可记录睡眠时长和主观疲劳；分别展示预计消耗、已用精力和当前剩余；计划超额时提醒减少安排。
- **活动管理**：创建、编辑、删除、完成与重新打开活动；支持学习、工作、兴趣、运动、生活家务和休息，设置时间、精力、认知负荷、优先级、紧急状态及结束条件。
- **行动建议**：根据当下精力、意愿、可用时间、紧急程度和最近高负荷活动给出最多三个选择；显示推荐理由，可以接受、跳过、换一组。
- **专注与停止**：选择活动开始计时，可暂停、恢复、提前完成或暂时停止；到点后询问是否休息，可继续五分钟；不自动完成活动，也不强制停止。
- **自由时间**：预留开始时间、时长和想做的事，随时开始；不以完成学习任务为前提，不评分、不惩罚。此版本是时间保留卡片，没有定时通知或日历同步。
- **每日收尾**：看到已完成事项，记下生活中的小事；将未完成活动与新的想法保存到「以后再做」，记下明天最想继续的一件事，然后结束规划；随时可以重新打开今天。
- **本地持久化**：预算、活动、状态、自由时间、收尾草稿、主题、运行中或暂停的计时器均可刷新恢复。
- **浅色 / 深色主题与响应式布局**：桌面侧栏、手机抽屉导航；弹窗支持键盘焦点限制、Esc 退出，并尊重减少动画的系统偏好。

首次打开包含四个可修改、可删除的示例活动；没有虚构的完成记录。

## 使用方式

1. 在「今日精力预算」调整当天预算，按实际状态选择「充沛 / 一般 / 疲惫」。
2. 把想做的事加入活动清单，给它一个合适的结束条件，而不只是设置时长。
3. 选择当前意愿和可用时间，看一眼推荐理由，选一个足够合适的行动。
4. 到时间时检查自己的感受。完成、继续或暂时停下，都可以。
5. 晚上进入「每日收尾」，收好还想做的事，然后安心结束今天。

精力点数是主观规划的刻度，**不是生理能量测量**。预算不必用完，完成数量也不是对一天价值的评价。

## 架构

```text
src/
  types.ts           领域类型：活动、每日状态、计时器、推荐结果
  data.ts            分类、日期、新建每日状态与首次示例数据
  recommend.ts       纯函数：可解释的推荐、精力汇总
  storage.ts         版本化存储、结构校验、异常处理与跨日恢复
  useCompanion.ts    React 状态编排、持久化、日期切换与计时操作
  components.tsx     可复用弹窗、活动表单、图标与元信息
  App.tsx            Dashboard、活动列表、以后再做、每日收尾
  styles.css         Tailwind 入口、视觉系统、主题与响应式布局
  *.test.ts          推荐和持久化单元测试
```

推荐与存储不依赖 React，便于单独测试、替换或扩展。UI 通过统一状态操作更新数据；后续趋势分析可基于 `days` 和活动的日期、负荷、完成时间扩展。当前模型尚未记录逐次专注会话或实际耗时，不能把计时器时长当作精确行为数据。

### 推荐规则

- 只考虑当前日期、尚未完成且未被暂时跳过的活动；活动必须能放进可用时间。
- 预计消耗不能超过剩余预算；预算耗尽或状态疲惫时，不推荐高负荷活动。
- 优先级和紧急程度影响排序；「轻松一下 / 活动身体 / 专注」会提高匹配类型的排序。
- 最近完成的活动若为高负荷，且在 90 分钟内，会优先提供休息和低负荷选择。
- 即使有紧急任务或预算已经用完，仍可以休息。没有合适活动时提供一个不消耗预算的短暂留白；它也可以被跳过。
- 没有复杂优化、自动安排或生产力评分；推荐顺序与对应理由都由本地规则生成。

### 数据与计时约定

- 存储键为 `liubai-energy:v1`，包含版本号和运行时结构校验。
- 「预计消耗」包括今天计划与已完成的活动；「已用精力」只累加已完成活动的估计点数，并非实时测量；剩余为预算减已用精力。提前停止且未完成时不扣除点数。
- 使用浏览器的**本地日历日期**。到新的一天重新生成每日预算与状态，不复制昨天的活动；以前没完成的计划显示在「以后再做」，由用户决定是否移回今天。
- 计时器保存绝对截止时间，避免靠逐秒递减造成后台或刷新漂移；暂停保存剩余秒数。刷新后若已到点，会显示停止提醒。浏览器关闭时没有后台通知，重新打开页面才会检查截止时间。
- 修改系统时间会影响剩余时间；本工具不是计时精度或健康监测工具。
- 收尾草稿随输入保存；勾选要转移的活动在提交收尾时处理。明日意愿是一条文字记录，不会自动创建任务或挤进次日计划。
- localStorage 隔离于浏览器、设备及站点来源。切换端口、清理站点数据、隐私窗口退出或更换浏览器可能无法访问原数据；此阶段不提供云同步或导入导出。建议在同一个标签页使用，暂不处理多个标签页同时编辑的冲突。
- 存储写入失败时会在页面提示；损坏或不兼容的数据不会被静默覆盖，只有确认使用新工作区后才替换原数据。原始记录可通过浏览器开发者工具的 Application / Local Storage 备份。
